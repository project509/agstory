# 00-plan — the art/UI overhaul as parallel agent waves

Synthesised 2026-09-13 from the seven verified reports (COMBAT, KIT, HALL, TOWN, STAGE, PIPE, RULES) and CRITIC. RULES is the law for every unit below; where a report's Fix and RULES disagree, RULES wins and the unit says so. Nothing in this plan changes a canon number (docs/_source is canon) or weakens a canon-guard test; every ambiguity the designer has not ruled lands behind a switch with the recommended default and is listed once in §6.

## 0. How to read this plan, and the rules every unit obeys

### 0.1 What a unit is
One agent, one commit series, one goal. Each unit lists: the CONFIRMED findings it closes (by id), the files it OWNS absolutely, the assets it produces and their generator route (PIPE's legend: LUA = headless Aseprite via tools/aseprite/lib.lua; PY = tools/art/*.py; SLICE = tools/art/slice.py from a manifest rect; SHADER = no PNG; none), the acceptance (the fixture shot it must show, the test that asserts it, the refdiff target if any), the shot command it uses to see its own work, how it keeps `tests/unit/test_screens.gd`, `tests/unit/a11y_smoke.gd` and `tools/lint_motion.sh` green, and a size (S/M/L).

### 0.2 Ownership and the isolation rule
- No two units in one wave own the same file. The seven hot kit files — `game/ui/Widgets.gd`, `Theme.gd`, `Frame.gd`, `SceneStage.gd`, `Cards.gd`, `Palette.gd`, `Type.gd` — have exactly ONE owner per wave (named in each wave's ownership table); so do `game/core/GameSettings.gd`, `game/core/ScreenRouter.gd`, `game/core/GameState.gd`, `tools/verify.sh`, `tools/lint_motion.sh`, `tests/unit/a11y_smoke.gd`, the scene/actor manifests, `docs/13-ui-ux.md`, `BUILD_STATE.md` and `build/plan/audit.json`.
- A unit that needs a change in a file it does not own writes the exact edit to `build/plan/handoff-<key>.md` in the shape the existing handoffs use (`## N. <file>:<line>` then an `old:` block and a `new:` block per edit, one edit per heading, nothing applied by the unit). The orchestrator applies every handoff between waves, then runs the full gate before the next wave starts. Write the handoff file FIRST (even empty) and append as you go — write-as-you-go is a hard rule here (LESSONS: two runs were lost to usage limits).
- **Within a wave a unit may reference only what exists at the wave's start or what the unit itself creates.** New theme variation names are strings and fall back harmlessly when missing, so a code unit may name `"PanelStamp"` in the same wave the chrome unit registers it; a code unit may NOT name a PNG path it does not emit (the boot gate fails on `Failed to load`), and may not call a function another unit is adding in the same wave. Textures cross unit lines as `Texture2D` parameters; `game/ui/Icons.gd` (W1-ICONS) is the only file that names icon paths; `Theme.gd` is the only file that names 9-slice paths; scene JSON is the only place that names strips.
- Never edit a test file you do not own; add `tests/unit/test_<key>.gd`. Tests are four-space indented. Indentation is per FILE: `Market.gd`, `RaidPrep.gd`, `Results.gd`, `Badge.gd`, `Bar.gd`, `Boot.gd`, everything under `game/core/` and `sim/` and `tests/` use spaces; the rest of `game/ui/` and `game/screens/` use tabs (RULES §5). GDScript refuses a mixed file.
- Every Godot invocation goes through `tools/with_godot_lock.sh`. No `_ready()` logic — screens draw in `build()`/`on_enter()` (RULES §1 harness fact). No `class_name` references (invariant 7/8).

### 0.4 Green, and how a wave ends
A unit is done when: its shot (read with the Read tool) shows the thing; its new test passes; `verify.sh --fast` is green; `a11y_smoke.gd` passes both sweeps (26 mounts, no new `warn` unless the unit says so); `lint_motion.sh` prints `MOTION LINT OK`. A wave ends when the orchestrator has applied every handoff, run the full `verify.sh`, `shot_all.sh` and `diff_all.sh`, and recorded the 13 refdiff numbers in BUILD_STATE. The game must be playable end to end (test_full_loop) after every wave.
