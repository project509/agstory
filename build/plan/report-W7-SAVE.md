## Judgement calls

1. **`active_run` snapshots the party and the loadout, which the plan's field list does not name.** The plan's shape is `{encounter_id, master_seed, party_ids, resolved, difficulty_mult, ninja_pulled}`. Those six alone do not reproduce the fight: `record_attempt()` applies the raid's morale deltas and `spend_loadout()` empties the cupboard before the autosave, so a replay rolled against the live roster and an empty loadout is a different fight from the one the player watched — which defeats the entire point of the field. `party` (a `Raider.to_dict()` per departed raider) and `loadout` are therefore stored beside the six. The six named keys are all present and all read; nothing was renamed.
2. **`raid_history` does not exist, so `active_run` is not carried on it.** The plan and RULINGS both say the options are "carried on the `raid_history` attempt record too". `grep -rn "raid_history"` over the whole tree returns nothing outside the plan files: there is no per-attempt history record in this build — `attempts` and `cleared` are id-keyed counters and `last_result` is transient. There was nothing to carry the options on, and inventing a history block would have been a fifth top-level save key in the wave whose job is to FREEZE the shape. Recorded rather than resolved; if a later wave wants an attempt history it is a key inside `flags` or a post-1.0 bump.
3. **`describe_reward()` and the rest of `Achievements` default `rp_live` to TRUE.** The ruling made the switch's shipped value true, and a screen that called `describe_reward(rec)` with no second argument would otherwise have printed the alternative's coin figure while the claim paid reputation. The parameter is kept (the alternative has to stay reachable); only the default moved.
4. **The docs/15 row is proposed in `build/plan/q-W7-SAVE.md`, not handed over as an exact edit.** The plan's handoff line asks for "the v17 BL row" in `handoff-W7-SAVE.md`; the ownership rule says a docs/15 row a non-owner needs goes to `q-<KEY>.md`. Both were followed: the row is written in full in the q- file and the handoff's header says where it is. An exact-anchor edit would not have survived the wave anyway — W7-DOCS is rewriting docs/15 around BL-110..BL-143 right now.
5. **§7's status line was added even though the contract only names the four rows, the freeze and §7.3.** §7 is entirely built and its header still said 🔷 PROPOSED; a section that says the wrong thing about itself is what sends the next reader looking for work that is done (LESSONS, twice). One sentence, inside the section this unit owns.
