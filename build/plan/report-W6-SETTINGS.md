## Judgement calls

1. **Hidden rows live in `HIDDEN_ROWS`, not in `ROWS` with a flag.** The Build note said "ROWS keeps the entry with `hidden: true`" so that the count test reads the visible list. `tests/unit/test_text_scale_layout.gd:1255-1273` (not this unit's, no wave-6 owner) walks `SettingsScreen.ROWS` and asserts every entry is BUILT and its cell measured — a flag would have turned that test red for the whole wave, or needed a handoff that leaves the gate red until the close. Splitting the table (`ROWS` = as shown, `HIDDEN_ROWS` = kept for their keys, `all_rows()` = the inventory) meets the note's stated purpose (every counting test reads the visible list, unchanged) with no cross-file edit. W10-DELETE deletes from `HIDDEN_ROWS`.
2. **"The CVD ramp on the morale pips" — the Settings screen has no morale pips**, so the acceptance as written could not be shot on that screen. The ramp row's control draws the ten bands as plates beside its chip (the volume row's own shape), which is a truthful preview of the option and the one place the choice can be seen before any roster draws it. The two shipped PLATE sites (Roster's histogram, RaiderDetail's sparkline) are `handoff-W6-SETTINGS.md` §1-§2; the TEXT-tint sites stay on the reference ramp on purpose — RULES §1 ("do not route `morale_color()` through the CVD ramp") and `test_palette_cvd.gd` (band 0 as text measures 1.35:1). The Findings' "Palette reads it at the `band_color` door" is honoured as `band_color_active`, the who-aware door that already existed; `band_color` itself is static, node-less and pinned to the reference ramp.
3. **The Music row carries no note** (contract: "no note"), which leaves its description column empty; an in-world note naming the beds would be a promise until W7-AUD-AMB lands. Accepted as the contract says.
4. **Display keys apply on press as well as on Apply**, mirroring `display_aspect`'s existing idiom — a window mode you cannot see until a restart is a choice you cannot make. Apply still runs the applier with the stored values (the pinned behaviour).
5. **`project.godot` opens fullscreen, so every non-headless tool run now flashes a fullscreen window** (shot.gd, diff_all, perf_probe). Godot's `-w` keeps them windowed; used here for this unit's shots and handed off for `shot_all.sh`, `diff_all.sh` and `verify.sh:322` (§5-§7). The plan's "shot.gd unaffected (SubViewport)" holds for the PICTURE; the flash is desktop ergonomics only.
6. **The windowed size allows for the OS's chrome** (`WINDOW_CHROME` 16x48) rather than measuring it, because the measurement is taken on a fullscreen window (no decorations) at the moment the choice is applied.
7. **The sidebar's second paragraph** (C21's "data/tuning" sentence) became the F11 / Esc line rather than being deleted — a true sentence a player can use, in the slot the reviewer's eye already lands on.
